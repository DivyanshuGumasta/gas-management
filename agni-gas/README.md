# Agni Gas Agency — cylinder ledger & billing

Offline Windows application now, server-ready later. Flask + HTML/CSS/JavaScript + SQLite.

## Run it

```bash
pip install -r requirements.txt
python app.py              # browser development mode -> http://127.0.0.1:5000
python desktop.py          # desktop application window
python seed_demo.py        # OPTIONAL sample data; never run on the client's live DB
python -m unittest discover tests
```

Build the Windows executable on Windows with `build_exe.bat`.
Data lives in `./data/agni.db` during development or `%APPDATA%\AgniGas` in the executable build. Daily backups are stored beside the database (newest 30 retained).

## Architecture rules

- Flask serves page shells from `templates/`, static assets, and the JSON API under `/api`.
- Pages contain no business data. JavaScript loads and saves data through `static/js/api.js`.
- API/UI money values are rupee strings (for example, `"1450.50"`); the database stores whole paise as integers.
- Bill numbers are generated by `db.next_number()` inside the transaction that saves the record.
- SQLite is the local database. Keep database access and business rules separate from page rendering so the server deployment can reuse the API.

### Moving to a server

1. Deploy the Flask API with a server database and keep the API contracts stable.
2. Host the static files and page shell; configure `apiBase` in `static/js/config.js` if frontend and API use separate origins.
3. Add authentication, permissions, HTTPS and an explicit backup/restore plan before multi-device use.

## Purchase and supplier rules

- Suppliers and Purchases share one navigation workspace, but their records and API responsibilities remain separate.
- A supplier's balance is opening payable/advance + active purchase totals − active supplier payments. Positive means **To pay**; negative means **Supplier advance**.
- Supplier payments may be allocated to one purchase or recorded as a general supplier payment/advance. An allocated payment cannot exceed that purchase's remaining due.
- Cylinder sizes must be linked to a supplier before they are available in that supplier's purchase form. The purchase API independently checks the link at save time.
- Ordinary goods (regulators, stoves, hoses, etc.) are master catalogue entries. **Create and edit master items in Stock & Price only.** Supplier profiles may link an existing catalogue item and maintain only that supplier's purchase rate. The purchase form may select only items linked to its selected supplier.
- Cylinder stock remains separate from ordinary goods because cylinders track full, empty, damaged and customer-held quantities. Ordinary catalogue items use unit-based stock quantities.
- A purchase stores the quantities/rates used at the time and any immediate payment. The supplier's original invoice is optional at registration and can be attached or replaced later from the purchase detail screen (PDF/image up to 5 MB). The app never issues a bill or invoice to the supplier.
- Full cylinders received increase full stock. Empty cylinders returned to the supplier reduce available empty stock and are not included in the purchase subtotal. Newly purchased empty cylinders increase empty stock and use the configured cylinder security price.
- GST is calculated on the purchase subtotal. Remaining due is payable later through the supplier ledger.

## Stock lots — cost tracking, oldest first (FIFO)

The agency's profit must not change when the buying price changes. A cylinder bought at 1,300 and sold at 1,500 is a 200 profit forever, even if the next purchase is at 1,400.

- **Every purchase of full cylinders creates a lot** (`stock_lots`): the purchase it came from (its "pid", `purchase_id`), the date, how many were bought (`qty_in`), how many are still on the shelf (`qty_left`) and the price paid per cylinder (`unit_cost_paise`). Refills and brand-new full cylinders both create full cylinders, so both go into the lot at the purchase rate.
- **Sales take from the oldest lot first** (by purchase date, then entry order). Nothing else decides the order. A purchase entered late but dated earlier is still older.
- **Every sale records which lots it took from and at what cost** (`lot_consumptions`). Profit of a sale = selling price − recorded cost. Today's buying price is never used for old cylinders, so old profit never changes.
- **Cancelling a sale** marks its rows `reversed` and puts the cylinders back into the same lots (nothing is deleted).
- **Existing stock** at the time tracking starts becomes one *opening stock* lot per size, at that size's saved buying price. Opening stock is always sold before purchases.
- If the lots ever run short (stock added by hand without a lot) the missing cylinders are costed at the size's latest buying price and saved with no lot, so a sale never fails because of tracking.
- `cylinder_types.full_qty` stays as the quick on-hand count the screens read. The lots must always add up to it; lots are the cost record, not a second stock count.
- **Not in the cost yet:** deposits (they depend on the damaged-cylinder/security rules still to be decided) and empty cylinders (they carry no gas cost).
- Code: `lots.py` (`add_lot`, `consume_fifo`, `restore`, `cost_of`, `create_opening_lots`). Read-only API: `GET /api/stock-lots?cylinder_type_id=&open=1` lists lots oldest first with the supplier, purchase number, cost and stock value left. This is also the table the Excel export will use.
- **Rules for code still to be written:** Sales must call `lots.consume_fifo(db, type_id, qty, "sale", sale_id)` for every full cylinder that leaves, and `lots.restore(db, "sale", sale_id)` when cancelling. Stock & Price "Adjust stock" must add a lot (`source='adjustment'`) when it adds full cylinders and consume from lots when it removes them. Cancelling a purchase (not built yet) must remove its lot only if none of it has been sold.

## Deliberate scope boundaries

- Purchase cancellation/reversal is not implemented. Do not delete purchase rows manually; they affect stock and supplier balances.
- Supplier archive is allowed only when its payable/advance balance is settled. Historical records are retained.
- Stock & Price is a separate unfinished module. It will own creation/editing of cylinder types and ordinary catalogue master items; the supplier/purchase screens only select and link them.
- Export dropdowns on supplier and purchase screens currently call the shared customer export placeholder. Actual PDF/Excel exports belong to the reports/export implementation. Supplier statements can be printed from the supplier profile.
- The supplier's uploaded invoice is the source document. The purchase detail page is only an internal ledger entry; it has no print/share action and is not a generated invoice.
